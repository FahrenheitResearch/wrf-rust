Diagnostic variable reference

All 125 variables registered in the wrf-core diagnostic registry, in registry order. Every entry is callable from Python as getvar(f, name) and from Rust as wrf_core::getvar. Name lookup is case-insensitive, and every alias is equivalent to its canonical name.

Generated from crates/wrf-core/src/variables.rs at v0.3.0 (351b8f3) via cargo run -p wrf-core --example dump_variables → data/variables.json → node docs/tools/render-diagnostics-table.mjs. The extractor reads the registry directly (no source parsing for data fields) and cross-checks the group labels against the live registry, failing on any mismatch.

Reading the table

  • Units are the defaults; most fields convert via the units= keyword (for example units="degC").
  • Dim is the output shape per time step: 2-D (ny, nx) or 3-D (nz, ny, nx). A few stacked products (for example cape2d, uvmet) return a leading component axis in addition to the listed dimensionality.
  • Group is the section of the source registry the variable is defined in.
  • Variables whose description references ecape-rs or ECAPE solve an entraining-parcel model per column and are the most computationally expensive entries; consumers commonly schedule them separately.
  • Names not in this registry fall through to raw WRF file variables (RAINNC, PBLH, TSK, ...), which are readable by name but are not diagnostics and are not listed here.
