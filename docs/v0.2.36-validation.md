# wrf-rust 0.2.36 validation

`0.2.36` is a performance-only stable-line release based directly on
`v0.2.35` (`fdee84ca4c95ce9af8e56b61b323b84c0bbd301a`). The later 0.3/0.4
science work remains on its existing line and is not part of this release.

## Source scope

The performance backport changes only these five Rust-core files:

- `crates/wrf-core/src/diag/cape.rs`
- `crates/wrf-core/src/diag/severe.rs`
- `crates/wrf-core/src/diag/srh.rs`
- `crates/wrf-core/src/hdf5_reader.rs`
- `crates/wrf-core/src/met/thermo.rs`

It deliberately excludes the post-0.2.35 DCAPE/DCP cache optimization because
those diagnostics did not exist in the 0.2.35 registry. No Python API,
diagnostic registry, formula constant, ECAPE dependency, or return type is
changed.

## Correctness gates

Fixture: `wrfout_d03_2023-01-05_09_00_00`, 2,388,958,814 bytes,
800 x 800 x 79, SHA-256
`0d9507867db691074226ca54827d1e9eddc5848af47b3baf27de451e828a77e6`.

- Rust core: 55 passed, 0 failed.
- Registered-diagnostic sweep: 96 succeeded, 0 errors.
- `v0.2.35` versus backport: 0 mismatches across concrete Python return type,
  shape, dtype, raw array SHA-256, finite/NaN/Inf counts, minimum, and maximum.
- WRF-Runner `New-PC-Updates` contract at commit
  `fe2e5405ce818824a50c4bc4ef2b506ec07dc41e`: 0 P0/P1 failures across the
  recorded `getvar`, `interplevel`, `latlon_coords`, `ll_to_xy`, `WrfFile`, and
  Cartopy contracts.
- Six-worker WRF-Runner-style pool: all 18 task hashes and shapes matched
  `v0.2.35`; no hangs or worker failures occurred.

## Measured performance

All timings below used the same real fixture and a 24-thread Linux node.

| Workload | v0.2.35 | v0.2.36 backport | Result |
| --- | ---: | ---: | ---: |
| All 96 registered diagnostics | 415.76 s | 300.92 s | 1.38x |
| Excluding aggregate `cape3d` and ECAPE-heavy family | 162.11 s | 65.93 s | 2.46x |
| WRF-Runner literal call contract | 62.95 s | 42.73 s | 1.47x |
| WRF-Runner-style 6-worker batch, mean of two | 48.27 s | 35.25 s | 1.37x |

The six-worker batch sampled mean aggregate peak RSS at 23.38 GB for
`v0.2.35` and 22.68 GB for the backport, a reduction of about 703 MB (3.0%).
It peaked at 179 threads with the existing 24-thread Rayon default and
completed without a hang. Capping Rayon to four threads per worker was slower
on this machine (71.71 s), so this release does not impose a global thread cap.

The approximately 3.25x figure from the expanded diagnostic audit uses one
process and one shared `WrfFile`, allowing caches to be reused across products.
WRF-Runner constructs separate file handles in process workers, so that number
must not be advertised as its end-to-end speedup.

## Installation note

PyPI version ordering places the already-published 0.4.x line above 0.2.36.
Consumers selecting this compatibility line must install it explicitly:

```bash
python -m pip install --force-reinstall "wrf-rust==0.2.36"
```
